全文分成两部分：

## 一、基础 Markdown 语法测试

这一节只写原生语法。如果某一条在这里的效果和标准 Markdown 不一样，那就是 bug。

### 段落与换行

普通段落由一个或多个空行分隔。同一段内的换行（软换行）会被渲染成空格，
**不会**产生换行——这是 Markdown 反直觉但必须知道的一条。

```markdown
这是第一行
这是第二行（渲染后与上一行连在一起）
```

段落之后空一行，才是新段落。

### 文本样式

- 普通文本
- **加粗**
- _斜体_
- **_粗斜体_**
- ~~删除线~~
- ==高亮文本== ← 本站扩展，完整的边界规则见第二节的「行内高亮」
- <u>下划线</u> ← Markdown 原生没有下划线，这是直接写 HTML
- **包含*斜体*的加粗文本**
- _包含**加粗**的斜体文本_
- **_包含~~删除线~~的粗斜体文本_**
- ==**高亮里的加粗**==
- **==加粗里的高亮==**
- 行内代码 `hello, world`
- 行内代码里可以写反引号：`` `代码` ``
- 转义：\*这不是斜体\*，\==这不是高亮\==，\`这不是代码\`

- **无序列表：**
  - 苹果
  - 香蕉
    - 脐橙
    - 血橙
      - 赣南脐橙
- **有序列表：**

  2. 第二步：清洗处理
     1. 洗菜
     2. 切菜
  3. 第三步：下锅烹饪
- **任务列表（GFM）：**
  - [x] 已完成的任务
  - [ ] 待办任务 1
  - [ ] 待办任务 2
- **混合嵌套列表：**
  1. 第一层级
     - 无序子层级 A
     - 无序子层级 B
  2. 第二层级

### 代码

行内代码用一组反引号包住：`hello, world`。要在行内代码里写反引号本身，就用更长的反引号包起来：`` `代码` ``。

围栏代码块写对语言名才有高亮（`js`、`ts`、`python`、`c`、`bash`、`markdown`…）：

```javascript
// JavaScript 代码高亮测试
function helloWorld() {
  const message = 'Hello, World!'
  console.log(message)
  return true
}
```

```python
# Python 代码高亮测试
def hello_world():
    message = "Hello, World!"
    print(message)
```

不写语言名也能渲染，只是没有高亮：

```text
没有语言标记的代码块
```

## 二、自定义语法测试

本站只在原生之上加**两种长相**，其余能力都是这两者的组合或运行期增强：

| 层       | 长相            | 说明                                 |
| -------- | --------------- | ------------------------------------ |
| 行内扩展 | `==高亮==`      | 只在段落内生效，边界规则严格（见下） |
| 块级扩展 | `:::名称 … :::` | 六种指令，所有"富内容"的唯一入口     |

另有两条默认生效、不需要写语法的能力：**图片管线**（自动转码、多档 srcset、点开放大）
与 **VitePress 内置提示容器**。

### 行内高亮 `==…==`

渲染成 `<mark>`，淡琥珀底色，明暗主题各自配色，可以和其他行内语法互相嵌套：

- 中文==强调==中文 → 高亮
- 词==x==词 → 高亮（`==` 外侧是汉字）
- 这是 ==important== 的 → 高亮（`==` 外侧是空格）
- ==~~高亮里的删除线~~==
- ==带 `行内代码` 的高亮==

不会被误判的写法（可以放心写）：

| 写法            | 结果                                               |
| --------------- | -------------------------------------------------- |
| `a == b`        | 单个等号，不是标记                                 |
| `if (a==b)`     | `==` 两侧都是英文字母 → 按比较运算符处理，原样输出 |
| `x==1 且 y==2`  | 同上，函数式写法里不会破                           |
| 行内代码 `a==b` | 反引号先吃掉内容，`==` 不参与解析                  |
| 下一行是 `===`  | 那是 setext 标题，由块级规则先处理                 |
| `==未闭合`      | 原样输出                                           |

**边界规则一句话**：某一个 `==` 的两侧同时都是英文 / 数字 / 下划线时，它按比较运算符处理；
只要有一侧是中文、空格或标点，就按高亮处理。

### 块级指令总览

长相永远是同一个模式，`:::` 单独一行收尾：

```markdown
:::名称 参数
里面的内容还是标准 Markdown
:::
```

| 指令         | 作用          | 写法                               |
| ------------ | ------------- | ---------------------------------- |
| `:::github`  | GitHub 仓库卡 | `:::github vuejs/core`             |
| `:::link`    | 外部链接卡    | `:::link https://example.com 标题` |
| `:::figure`  | 带图注的图片  | `:::figure caption="图注"`         |
| `:::quote`   | 带出处的引用  | `:::quote 《书名》`                |
| `:::columns` | 多列并排      | `:::columns 2`（用 `---` 分栏）    |
| `:::gallery` | 图片网格      | `:::gallery`（或 `:::gallery 3`）  |

下面逐个实测。

### `:::github` —— GitHub 仓库卡

:::github https://github.com/emanyzwww/EmanyzwwwDocSite
:::

构建期**只产出仓库名和一条真链接**（零网络请求），描述与 ★ 数在你把卡片滚进视野时才由浏览器补；
取不到数据就一直显示那条链接，不会卡在加载中。

### `:::link` —— 外部链接卡

带自定义标题（**标题里含空格时必须加引号**，否则会被切成多个位置参数而报错）：

:::link https://vitepress.dev "VitePress 官方文档"
:::

不写标题时用域名兜底：

:::link https://baidu.com
:::

### `:::figure` —— 带图注的图片

图注由 `caption` 参数给，**不要**改用图片的 `title`（那是悬停提示）：

:::figure caption="图注写在 caption 参数里，图片本身仍然走媒体管线：转 webp、多档 srcset、点开放大"
![示例配图](./figure.png)
:::

> 本节与下面的画廊引用的是同目录的 `figure.png`、`gallery-1.png`、`gallery-2.png`、`gallery-3.png`。
> 换图时**同名覆盖**即可，不用改 Markdown；名字写错或文件缺失时，构建会明确报「找不到图片」，
> 不会静默产出一张裂图。

### `:::gallery` —— 图片网格

连着写几张图会被 Markdown 当成同一个段落，所以网格必须显式包一层：

:::gallery 3
![网格示例一](./gallery-1.png)
![网格示例二](./gallery-2.png)
![网格示例三](./gallery-3.png)
:::

- 列数写 `2` / `3` / `4`，不写默认 2；
- 每张图仍然可以点开全屏查看；
- 窄屏降为单列，中等宽度下 3 / 4 列自动退成 2 列。

### `:::quote` —— 带出处的引用

出处直接写在指令后面：

:::quote 《C 程序设计语言》
第一个示例程序打印 “hello, world”，从此奠定了它作为编程入门第一课的传统地位。
:::

也可以用具名参数 `source=`，内部还能是多段、列表、代码：

:::quote source="《The C Programming Language》"

Kernighan 与 Ritchie 在这本书里做了两件事：

- 用一个打印 “hello, world” 的程序开了头
- 让这句话变成了几十年的传统

:::

### `:::columns` —— 多列并排

用**单独一行的 `---`** 分隔各列，每列内部都是完整 Markdown：

:::columns 2

**左栏**：列数写 `2` 或 `3`，不写默认 2。

- 每列内部是完整 Markdown
- 列表、代码、图片、甚至嵌套其它指令都行

---

**右栏**：窄屏（< 704px）自动变成单列——手机上两栏中文每行不足 15 字，没法读。

```js
// 列里放代码块也可以
const columns = 2
```

:::

### 图片管线

图片不需要写任何语法，构建期自动完成四件事：

| 项           | 行为                                                           |
| ------------ | -------------------------------------------------------------- |
| 展示图       | 转成 webp，出 336 / 672 / 1008 三档 `srcset`                   |
| 原图         | 原样进产物，只在点击放大与下载时才被请求                       |
| 独占一段的图 | 自动升成 `<figure>`，点一下全屏查看（翻页 / 缩放 / 下载原图）  |
| 尺寸         | 自动从图片头部读出，防跳版；确实要改显示尺寸才用 `{width=100}` |

行内的图**不会**升级（升级会切断句子）——一行里连写两张，两张都是行内图：

文字 ![图一](/placeholder.svg) 与 ![图二](/placeholder.svg) 之间夹着文字。

只改显示尺寸、不参与放大的写法：

![占位图](/placeholder.svg){width=100}

想让某张图**不能**点开放大（纯装饰的小图标），加 `{data-plain}`：

```markdown
![装饰](./ornament.png){data-plain}
```

### 行内 HTML

配置里 `html: true`，所以正文可以直接写 HTML（少用，需要时可用）：

<div style="padding: 12px 16px; border-radius: 10px; background: var(--bg-surface-alt);">
  这段是直接写在 Markdown 里的 HTML。
</div>

### 边界与坑

**1. 指令不能直接放进提示容器里**——两者共用 `:::` 作收尾标记，会互相抢闭合行。
解决办法是让外层的冒号比内层多（里短外长）：

```markdown
:::: tip 这样才行
:::github vuejs/core
:::
::::
```

**2. 围栏代码块里的 `:::` 是内容**，不会被当成指令——所以上面这些示例才能正常显示。

**3. 指令可以互相嵌套**，内部 Markdown 照常解析：

```markdown
:::quote 《某本书》

:::github vuejs/core
:::

:::
```

**4. 写错了会在构建期失败**，并指出文件和行号，不会等到线上才发现：

- `未知的指令类型：:::gihub`（会列出可用指令并猜你想写哪个）
- `指令 :::github 没有闭合`（忘了写收尾的 `:::`）
- `:::github 缺少仓库名`（参数没写）

**5. 裸露的 GitHub 仓库链接不再自动变卡**——现在它就是一条普通链接。
要用卡片请写 `:::github owner/repo`，`pnpm check` 会提示残留的旧写法。
